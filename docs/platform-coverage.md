# Platform API coverage audit

Snapshot: **2026-11-24**, application baseline **`b14c48f`**. This is a source audit and a bounded client-feature inventory, not a declaration of working parity. The user-facing target is the agreed current Telegram/MAX client feature set. A protocol method, an upstream wrapper, a frozen ContactHub method, a plugin handler, a core effect, a UI control and a tested server workflow are separate evidence levels.

The full extracted inventories, public source snapshots, checksums, per-row DTO/event/core/test crosswalks and extraction tools are retained in the local audit evidence bundle. Only this public-safe summary is committed. Application work after the baseline is deliberately not counted here. See [contract amendments](api-contract-gaps.md) for the accepted four-action bridge subset and the remaining proposals.

## Shared contract versus the running application

The [frozen registry](../schemas/methods/registry.json) contains **121 methods: 119 core→plugin + 2 plugin→core secret-store services**. It has **18 event names** ([event schema](../schemas/events.json)). At the baseline Telegram implements **14** core→plugin methods, including lifecycle/auth; **105** remain. MAX and WhatsApp plugins are absent. See the [Telegram baseline handler table](../plugins/telegram/README.md).

The Rust host can make typed registry calls and ingest all frozen event variants, but the application [CoreOperations](../app/ui/src/core/index.ts) exposes only **16** UI operations. `listChats` and `search` read local state; they are not platform dialog refresh and global server search. `history` and text outbox are working architectural routes, not media/reaction/admin/privacy routes. Even a complete 119-method adapter requires additional typed application operations, DB projections, controls and tests. [Application bridge](../crates/ch-app/src/bridge.rs) · [local ingest effects](../crates/ch-core/src/ingest/local.rs) · [application contract](app-api.md).

The following matrices use **candidate** to mean that a frozen mapping can be implemented after resolving parameter, identity, pagination and event differences. It does not mean the plugin advertises the capability.

## Scope decisions and acceptance evidence

Legitimate exclusions must be narrow and named: MTProto envelopes/auth-key/DC/chunk/sync internals are adapter/SDK plumbing; bot-only **server** methods are excluded from personal accounts when the official method page says so; mobile SMS relay/device-push registration need not become desktop controls. Bot interaction, user checkout, Business ownership, calls, stories, admin/owner rights and premium-gated features are not bot-only exclusions. Secret chats need an explicit product decision and E2E state design: absence in Telegram Desktop or Telethon's high-level convenience API alone does not decide the requested scope. [Telegram secret chats][tg-secret].

The Telegram method ledger retains 30 official bot-only and 7 mobile SMS-job exclusions, 21 protocol-internal entries and 30 internal-or-review entries. The latter remain reviewed individually: notifications, Terms/report/support or appearance settings can have a user workflow even when they share a plumbing namespace. Unknown/documentation-lag entries remain on the backlog with their raw name and signature. MAX/WhatsApp wrapper omissions remain **upstream unknown / adapter gap**, not proof the native client lacks the feature.

For each agreed feature family, completion requires: pinned source/access evidence; a frozen-method mapping or approved additive amendment; implemented capability and exact params/results; live update/refresh convergence; DB/core projection; reachable typed UI action; offline protocol/effect/UI tests and CI; then a separately authorized controlled server smoke test. Rate limits, role/tier restrictions and platforms without a feature must produce explicit supported-state/`NOT_SUPPORTED` behavior. A denominator such as 121 methods is not the acceptance criterion. Refresh the pinned scope at a planned milestone; this audit does not require chasing every future platform release forever.
